# USB 桥接配置

初始化NVS后调用 `hosino_bili_provision_start()`，不修改桌面、GPIO、下载模式或
网络服务。当前UART是主控制台、USB-JTAG是只输出的副控制台，因此本组件直接
对已有 `/dev/secondary` USB VFS 打开独立stdio输入/输出；不读取UART stdin。

协议为单行 `BILI_CONFIG {"base_url":"https://...","device_token":"..."}`。
自动配置工具额外附加16位十六进制 `request_id`（不保存到NVS），并只接受带有同一
编号的确认。发送密钥前，先用换行清除上次残留半行，再发送 `BILI_SYNC <编号>`，
收到 `BILI_SYNC_OK <同编号>` 才发送配置。旧的无编号成功/错误行均不会被误认。
行上限768字节，PSRAM缓冲/4KiB低优先级任务；未知行忽略，过长行丢弃至换行，
不回显输入。确认只返回固定成功/无效/长度/存储错误，无地址或密钥。
USB读取按驱动模式选择标志：已安装中断驱动时用O_NONBLOCK，默认无驱动的LL
轮询模式清除此标志。固定IDF5.5.5在无驱动且O_NONBLOCK时不会预读FIFO，同时
其可用字节计数只统计驱动环形缓冲，导致永远读不到输入。默认LL读取本身会立即
返回，仍通过EOF/clearerr和20ms等待轮询，不阻塞GUI。
诊断仅输出通道就绪、驱动模式、打开失败errno或首次收到数据计数，不输出字节。
主机工具只从私有JSON文件读配置，不接受命令行密钥参数：

```powershell
python scripts/Provision-Bili.py --port COM9 --config-file <私有JSON路径>
```

工具不进入下载模式，不发送复位序列；打开前将DTR/RTS设为False，并只通过串口
发送配置。只有收到完整 `BILI_CONFIG_OK <同编号>` 才报告保存成功；不使用延时猜测
重同步结果。私有JSON文件仍只有地址和令牌两个字段，编号由工具在内存中生成。
配置后关闭并重新打开哔哩哔哩应用，以加载NVS中的新值。

`hosino_bili_config_load/save` 同时提供给USB入口和应用设置页。PSRAM调用任务
同步等待完成；互斥锁串行化请求，NVS操作在短生命周期4KiB内部RAM栈任务执行。
写入前将配置复制到内部栈，完成后擦除临时配置；调用方和请求上下文在完成前
均保持有效。地址和令牌一起保存为固定456字节、版本1、零填充的单个blob
`hosino_bili/bridge_v1`，避免断电或写入失败后将新地址和旧令牌混配。
载入检查精确长度、版本、保留字节、字符串终止/零填充及地址/令牌策略，损坏则
拒绝使用；不迁移或读取此前未刷入的两个独立字符串键。
成功ACK只在整个blob写入且 `nvs_commit` 成功后产生；不擦除分区或其它命名空间。

地址和24至192字符令牌使用生产 `hosino_network_policy.h` 同一规则，保存前和
载入时规范化地址尾部斜杠。解析器只接受两个唯一ASCII字符串字段，JSON转义在
策略检查前解码；可选编号须为16位十六进制；无递归、无JSON树分配。

`tests/run_tests.py` 编译实际解析器、保存入口和内部任务存储实现，用RTOS/NVS
边界桩检查非法地址、CRLF/NUL令牌、过长行、固定命名空间/blob键、内部栈标志、
写blob/提交失败、旧记录保持整对或新记录保持整对，以及损坏blob拒绝载入。
它不模拟串口成功，不代表设备端USB收取、真实flash写入或断电持久性已验收。
