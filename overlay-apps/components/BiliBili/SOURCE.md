# 哔哩哔哩设备应用

项目原创 C++/LVGL/Brookesia 组件，Apache-2.0。只参考腕上哔哩的单列卡片、
大触摸目标和播放控制收纳思路，没有使用其 Android 代码或图片。
粉色电视图标为本组件生成的 RGB565 几何图形。

接口按 `server/bilibili-bridge/API-CONTRACT.md`；添加的播放状态查询用于
等待服务端完成转码参数准备，不让 LVGL 线程等待网络。

- 使用 Brookesia App 的状态栏和生命周期，不替换桌面或安装全局触摸处理。
  内容左右留28像素、底部留安全区；播放 controls 点画面呼出后自动收起。
- 首页、全键拼音/英文搜索、视频详情及前20分P、分页收藏夹/收藏视频、个人信息、
  扫码和每3秒状态轮询、明确点按收藏/移除、两档清晰度、五档码率与默认推荐。
  推荐采用所选清晰度的预算和服务端3秒样本质量校准，不是Wi-Fi实时自适应码率。
- `BiliMediaHooks` 仅在控制 worker 调用；解码回调仅复制 RGB565 到两个 PSRAM
  缓冲，GUI定时器呈现。改变清晰度、码率或进度会停止原会话，再从源时间重开。
  暂停也停止本地播放器并取消服务端会话，保留源进度；继续从该进度建立新会话，
  避免长时间暂停触发服务器写超时后恢复失效。
  选定清晰度的已知宽高/帧率作为显式受控流元数据传入播放器，仅补齐FLV解析器的
  零值；真实非零尺寸冲突或超出解码块对齐范围时拒绝，不从URL猜测视频尺寸。
- 单个12KiB PSRAM控制栈、最多两个排队命令、48KiB响应上限、12秒请求截止和
  1.8秒单次网络超时。关闭/后台使普通请求停止，清除排队操作；已知服务端播放
  会话由控制 worker 发DELETE取消。停止失败则保留资源并重试，避免悬空回调。
  请求头/响应读取仅在明确 `-ESP_ERR_HTTP_EAGAIN` 时沿同一连接有界续读，不重开
  连接或重发POST；收到末段立即检查完整性，截断响应不会当作成功。服务端准备
  错误保留 `code/message`（兼容旧字符串），与设备等待准备超过75秒分开显示。
  请求诊断只记录固定路由类别、阶段及数值；DNS失败异步记录本机IP/网关/DNS，
  不记录完整API路径、令牌、二维码、播放会话或原始错误消息；诊断本身不改DNS。
  DNS容灾由Bili控制worker在发送HTTP之前统一触发：保留正常DHCP主DNS及已有非零
  备份，只给空备份槽补223.5.5.5/223.6.6.6；配置域名IPv4解析明确失败后，可把
  已预置公共DNS移至前面并仅重查一次，原非零服务器保留在其余槽。此操作影响
  系统共享resolver，含60秒恢复冷却；不更改IP/网关/DHCP、URL/Host/SNI或证书。
  原生查询未终结时保持单flight，取消/截止仅放弃等待，回调持有独立引用至终结；
  不在原生失败回调内递归重查、不清全局DNS缓存，不重发已执行的HTTP/POST。
- UI不因轮询给全部项目设置禁用状态。导航请求序号阻止旧列表冒充新列表；
  播放快照只更新进度，不重建播放页。
- 连接配置存 NVS `hosino_bili/bridge_v1`：单个零填充版本blob包含地址和令牌，
  通过共享内部RAM栈存储任务执行，避免两键更新造成地址/令牌混配。只接受HTTPS；
  令牌24至192个无空白ASCII字符，走 Authorization 请求头；不输出日志、不嵌入
  私人凭据。设置页留空令牌保留原值。B站 Cookie 仅由服务端保管。
- 已通过当前 ESP-IDF 5.5.5/Xtensa C++ 编译参数的语法检查；完整构建、硬件触摸、
  在线播放、二维码手机确认和真实收藏变更需分别验证。服务未部署时显示真实网络
  错误，不提供假视频、假用户信息或假登录成功。

当前未下载封面/头像；采用文字卡片以限制TLS连接和位图内存。拼音使用固件已有
LVGL K26字典，属于单字候选输入。画面适应使用LVGL缩放，性能需实机衡量。
